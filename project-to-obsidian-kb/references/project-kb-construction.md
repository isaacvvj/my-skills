# 双库输出与证据契约

以 `PROJECT_ROOT` 内真实内容为唯一依据，生成相邻但职责分离的两个目录：

```text
嵌入式工程库：工程参照、模块机器清单、候选模板入口
Obsidian嵌入式知识库：少量导航、项目结论、资料蒸馏和验证记录
```

原工程始终保留为黄金基线。不要自动复制或迁移源码；真正抽取模板必须另行计划、复制到新工程副本并独立验证。

## 知识库最小连接图

```text
README
→ 00-首页与导航/项目导航
  → 工程库导航
  → 模块导航
  → 80-项目与实验记录/项目总览
  → 80-项目与实验记录/构建与验证状态
  → 20-芯片与开发板/硬件资料与板卡候选
  → 98-资料索引/资料清单
  → 98-资料索引/硬件资料蒸馏任务
  → 99-待确认
```

除非用户要求或模块已有稳定价值，不要创建"一模块一笔记"。模块候选集中在 `模块导航.md` 表格和工程库 `模块索引.json` 中。

## 证据

- L0：源码、配置、手册、原理图、资料转换稿、AI 建议。
- L1：本机构建、静态配置、ERC/DRC 或生产文件检查。
- L2：目标板功能验证。
- L3：多项目/多批次稳定复用并有回归或故障记录。

建立链接、复制资料或创建工程库清单均不能提升可信等级。
