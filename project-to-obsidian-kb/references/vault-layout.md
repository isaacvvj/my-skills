# 知识库输出契约

所有内容相对 `PROJECT_ROOT\Obsidian嵌入式知识库` 创建；原工程是唯一事实来源，不被修改。

| 目录 | 职责 | 默认内容 |
|---|---|---|
| `00_总览` | 项目入口与扫描范围 | `项目总览.md`、`扫描清单.md` |
| `10_嵌入式工程` | 工程结构、构建、配置、源码模块索引 | 只链接到原工程 |
| `20_芯片与开发板` | MCU、开发板、PinMux 和板级接口 | 从资料蒸馏，默认 L0 |
| `30_硬件模块与接口` | 传感器、执行器、电源、通信和连接契约 | 按当前项目增量创建 |
| `50_项目记录与验证` | 构建、烧录、上板和整机证据 | 验证范围必须分开 |
| `60_故障排查与经验` | 已发生且可复现的问题 | 无历史资料时保持空目录 |
| `98_资料索引` | 原始资料、转换稿、来源和版本 | 不复制整包资料 |
| `99_待确认` | 缺失、冲突、未验证事项 | 不用猜测填补 |

## 必填元数据

```yaml
source_path: <相对原工程或资料路径>
status: 草案
trust_level: L0
verification_scope: 未验证
```

## 证据等级

- `L0`：手册、原理图、资料或 AI 建议。
- `L1`：本机构建、静态配置、ERC/DRC 或生产文件检查。
- `L2`：目标板完成对应功能验证。
- `L3`：多项目或多批次稳定复用，且有回归/故障记录。

资料导入、Markdown 转换和笔记链接均不能提升证据等级。
