# 现有工程转模块参照规则

目标是帮助 AI 先读懂并安全参照当前工程，随后才决定是否将某一部分做成真正模板；不是移动、删除或自动重构原工程。

## 每个模块卡的最小内容

```yaml
type: 代码模块
source_files: [Core/Inc/foo.h, Core/Src/foo.c]
module_type: 驱动/算法/协议/控制/应用入口/厂商依赖/待确认
interfaces: [Foo_Init, Foo_Update]
reuse_status: 候选可复用模块
verified_compile: false
verified_hardware: false
trust_level: L0
```

正文必须说明：

1. **功能**：仅引用源码、README 或调用方能支持的描述；不能确定则写“待确认”。
2. **原工程入口**：头文件、实现、调用方、配置和测试路径的相对链接。
3. **对外 API**：保留原始函数、宏、结构体和协议字段名称。
4. **依赖**：直接 include、HAL/BSP、全局变量、时钟/PinMux、任务/中断、内存与初始化顺序。
5. **复用边界**：哪些内容可以复制，哪些属于项目专用，哪些必须保留在工程编排层。
6. **验证**：独立构建、目标板、整机和多项目复用的证据分开记录。

## 自动识别结果的处理

- 同名 `.c/.h` 或 `.cpp/.hpp` 是候选边界，不是最终边界。
- 从头文件解析到的函数声明、从源文件解析到的函数名、`#include` 列表，都只是快速阅读索引；复杂宏、回调、函数指针、跨文件全局变量和 RTOS 关系必须人工复核。
- 名称相同但路径不同、多个实现文件、缺少头文件、文件过大或解析失败时，保守标记为“待确认”。
- `main.*`、初始化、顶层状态机和调度代码默认留在项目参照层。
- 厂商 SDK、自动生成代码、启动文件、链接脚本和 IDE 配置只建立依赖索引，除非用户明确要求迁移。

## 抽取为真正模板前的门槛

1. 写清输入、输出、单位、时序、错误与安全状态。
2. 定义最小公共 API，移除或隔离项目全局变量和硬件耦合。
3. 确认 `.ioc`/`.syscfg`、PinMux、DMA、中断、时钟、BSP/HAL 和链接依赖。
4. 复制到新工程或专用模板候选目录后独立构建；不要从黄金基线剪切代码。
5. 对电机、执行器、通信、供电等敏感模块，完成安全边界检查和目标板验证后再复用。

## 源码保留原则

默认仅生成摘要、接口、依赖、函数签名、SHA256 和原工程相对链接；不要把整个源码目录复制到 Obsidian。需要跨环境交接时，应交付原工程，或只生成明确选择的关键片段并保留来源和哈希。
