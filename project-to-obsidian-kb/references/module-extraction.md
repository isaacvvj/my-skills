# 工程参照与模板抽取规则

## 当前工程先作为参照，而不是自动拆分对象

扫描器将 `.c/.h`、`.cpp/.hpp` 和同功能脚本聚合为模块候选，输出到：

```text
Obsidian嵌入式知识库/00-首页与导航/模块导航.md
嵌入式工程库/工程参照/<项目名>/模块索引.json
```

这两个位置是聚合入口，不为每个模块默认创建独立 Markdown。

## AI 读取顺序

```text
模块导航
 原工程头文件
 实现文件
 调用方
 构建与芯片配置
 原理图/资料
 构建与上板证据
```

机器清单中的 `public_api`、`defined_functions`、`direct_includes` 和 SHA256 只是阅读索引。必须人工确认复杂宏、回调、函数指针、全局变量、RTOS、中断、DMA 和硬件耦合。

## 进入模板候选前的门槛

1. 定义公共 API、输入输出、单位、时序、错误和安全状态；
2. 明确 HAL/BSP、SDK、PinMux、DMA、中断、任务、链接和构建依赖；
3. 将候选代码复制到新工程或模板候选副本，不从黄金基线剪切；
4. 完成独立构建后记录 L1；
5. 对硬件相关模块完成目标板验证后记录 L2；
6. 仅在稳定复用后形成可长期维护的模板模块和独立知识库笔记。

## 默认禁止自动抽取

`main.*`、顶层状态机、项目初始化、厂商 SDK、自动生成代码、启动文件、链接脚本、`.ioc`、`.syscfg` 和 IDE 配置仅作为依赖边界索引，禁止自动进入模板候选。
